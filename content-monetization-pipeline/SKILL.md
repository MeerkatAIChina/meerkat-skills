# Content Monetization Pipeline

## 简介
本 Skill 用于将**已完成生产的内容资产**（产品宣发视频、种草图文、品牌故事、直播切片等）转化为可分发、可追踪、可变现的全链路方案。核心目标不是生产内容，而是让已有内容在多个平台产生最大化的曝光与商业回报。

## 项目定位
- **定位**：分发型变现 Skill（内容资产 → 多平台分发 → 数据追踪 → 收益结算）
- **上游依赖**：`product-promo-video-maker` 或其他内容生产 Skill。若用户未提供内容资产，必须先调用上游 Skill 完成内容生产。
- **下游输出**：可直接执行的分发排期、平台适配规范、结算追踪模板。

## 适用场景
- 用户已有产品宣发视频，需要在抖音/小红书/TikTok/YouTube 等多平台分发并追踪 ROI
- 创作者矩阵运营：同一内容批量分发至多个账号/平台
- 品牌/KOL 需要设计 CPS/CPE/CPM 变现方案
- 线下门店（餐厅/零售/民宿）需要将线下活动转化为线上传播并引流到店

## 不适用场景
- 内容尚未生产（应先使用 `product-promo-video-maker` 或其他内容生产 Skill）
- 纯品牌曝光无变现目标（不需要本 Skill 的结算链路）
- 单一平台发布且无需追踪数据（手动发布更高效）

## 核心分析框架

### 1. 内容资产评估
任何内容在进入分发前必须先做变现潜力评分，避免"为了发而发"。

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| **产品信息完整度** | 25% | 0=无产品信息，50=有产品但无卖点，75=卖点清晰，100=卖点+价格+购买路径齐全 |
| **视觉吸引力** | 20% | 0=无视觉焦点，50=有画面但节奏差，75=节奏OK，100=3秒钩子+节奏紧凑+结尾CTA |
| **转化路径清晰度** | 25% | 0=无转化入口，50=有链接但隐藏深，75=路径明确，100=评论区置顶+主页链接+优惠码三位一体 |
| **平台适配度** | 15% | 0=单尺寸无法适配，50=需裁剪，75=有竖屏/横屏双版本，100=竖屏+横屏+图文+切片全版本 |
| **受众匹配度** | 15% | 0=内容与受众无关，50=相关但无痛点，75=痛点清晰，100=痛点+解决方案+紧迫感 |

**判定建议**：
- 80-100：可直接进入 Stage 2 分发策略
- 60-79：先补充转化路径/视觉钩子，再进入 Stage 2
- 0-59：不建议分发，返回上游重新生产内容

### 2. 变现模式矩阵

| 模式 | 全称 | 适用内容 | 关键指标 | 平台适配 |
|------|------|---------|---------|---------|
| **CPS** | Cost Per Sale | 产品评测/种草/教程/直播切片 | 成交转化率 | 小红书/抖音/视频号/快手 |
| **CPE** | Cost Per Engagement | 话题挑战/互动型内容/UGC 征集 | 点赞/评论/转发量 | 全平台 |
| **CPM** | Cost Per Mille | 品牌曝光/信息流/开机画面 | 播放量/曝光量 | 抖音/TikTok/YouTube/信息流 |
| **CPS+CPE 混合** | — | 高客单价产品+社群裂变 | 成交+互动双重指标 | 小红书/抖音 |

### 3. 平台分发适配规则

#### 抖音/快手
- **格式**：9:16 竖屏，分辨率 1080×1920
- **时长**：3-15s 黄金开头，完播率决定流量池
- **标签**：# 话题 + 位置 + 垂直标签（3-5 个）
- **发布时间**：11:00-13:00, 17:00-19:00, 21:00-23:00
- **CTA**：评论区置顶链接 + 主页橱窗
- **变现入口**：抖音小店/快手小店/第三方 CPS 联盟

#### 小红书
- **格式**：图文 3:4 或 视频 9:16，封面决定 80% 点击率
- **标题**：痛点/数字/对比/情绪（如"3个设置让无人机续航翻倍"）
- **标签**：5-8 个，前 3 个为热搜词，后 5 个为长尾词
- **发布时间**：7:00-9:00, 12:00-13:00, 18:00-20:00, 22:00-23:00
- **CTA**：正文底部"点击主页店铺" + 评论区置顶购买链接
- **变现入口**：小红书店铺/蒲公英平台/品牌合作

#### TikTok / YouTube Shorts
- **格式**：9:16 竖屏，3s 内必须出现 hook
- **节奏**：快节奏 + 字幕 + 音乐/音效匹配趋势
- **标签**：3-5 个 trend hashtags + 2-3 个垂直标签
- **发布时间**：对应时区 12:00-13:00, 18:00-20:00
- **CTA**：Bio link / 评论区 Linktree / 直播预告
- **变现入口**：TikTok Shop / YouTube Partner Program / 联盟营销

#### Bilibili
- **格式**：16:9 横屏为主，知识/评测/故事类 3-10min
- **节奏**：开头 10s 内给出核心价值承诺
- **互动**：弹幕引导 + 评论区置顶转化链接
- **发布时间**：11:00-13:00, 17:00-19:00, 21:00-23:00
- **CTA**：评论区置顶 + 视频内 QR 码/口播引导
- **变现入口**：充电计划 / 商单 / 淘宝客 / 自有店铺

#### 微信公众号 / 视频号
- **格式**：视频号 9:16 或 1:1，公众号图文 16:9 封面
- **节奏**：熟人社交，信任前置，适合深度种草
- **发布时间**：7:00-8:00, 12:00-13:00, 21:00-22:00
- **CTA**：公众号文章内嵌小程序/视频号橱窗
- **变现入口**：微信小店 / 小程序商城 / 私域引流

### 4. 发布排期策略

```
Day 0 (预热期):
  - 小红书：图文预告 + 投票互动
  - 抖音：15s 悬念切片
  - 微信：朋友圈倒计时海报

Day 1 (主发期):
  - 抖音/快手：主视频 09:00 首发
  - 小红书：完整视频 + 图文笔记 10:00 同步
  - TikTok：对应时区 peak hour 发布
  - B站：中长版本 12:00 发布
  - YouTube：长版本 + Shorts 切片同步

Day 2-3 (长尾期):
  - 抖音：评论区互动 + 二次剪辑发新视频
  - 小红书：评论区种草回复 + 关联笔记
  - 全平台：数据监控，表现好的内容追加投放

Day 7 (复盘期):
  - 数据汇总 → ROI 计算 → 优胜内容识别
  - 优胜内容 → 追加预算 / 二次创作 / 跨平台搬运
```

## Skill 工作方式

1. **内容资产评估**：用户上传内容或提供内容链接，先跑变现潜力评分
2. **变现模式匹配**：根据内容类型、产品属性、平台特征，推荐 CPS/CPE/CPM/混合模式
3. **平台分发策略**：选择目标平台矩阵，制定内容格式适配方案
4. **发布排期设计**：制定预热→主发→长尾→复盘的时间表
5. **追踪模板生成**：输出可执行的 ROI 追踪表和结算模板
6. **矩阵放大方案**：同内容多账号/达人合作/付费流量加持策略

## 主链路执行框架

### Stage 1: 内容资产评估（Content Asset Scoring）

**输入**：
- 内容文件或链接（视频/图文/直播回放）
- 产品信息（名称、卖点、价格、购买链接）
- 目标受众描述

**输出**：
- 变现潜力评分（0-100，含 5 维度明细）
- 评估结论：直接分发 / 先优化再分发 / 返回重制
- 优化建议清单（如果评分 < 80）

**质量标准**：
- 评分必须有 5 个维度的独立打分，不能只有一个总分
- 优化建议必须具体到可执行动作（如"第 3 秒插入产品特写"、"评论区置顶添加优惠码"）
- 评分 < 60 时必须明确拒绝分发，并给出返回上游的指令

### Stage 2: 变现模式选择（Monetization Model Selection）

**输入**：
- Stage 1 的评分结果
- 用户变现目标（卖货/涨粉/品牌曝光/引流到店）
- 产品客单价区间

**输出**：
- 推荐变现模式（CPS/CPE/CPM/混合）及理由
- 各模式的预估收益模型（公式 + 假设参数）
- 结算追踪模板（YAML/Excel）

**质量标准**：
- 收益预估必须给出公式和参数假设（如"CPS 佣金率 15%，客单价 ¥299，转化率 2% → 单订单收益 ¥8.97"）
- 必须明确说明"预估基于假设，实际以平台数据为准"
- 追踪模板必须包含：内容 ID、平台、发布时间、追踪链接、优惠码、播放量、互动量、转化量、收益

### Stage 3: 平台分发策略（Platform Distribution Strategy）

**输入**：
- 内容资产（视频/图文）
- 目标平台列表（用户指定或 Skill 推荐）
- 变现模式

**输出**：
- 平台矩阵设计表（平台 / 内容格式 / 适配动作 / 发布时间 / CTA 方案）
- 内容格式适配清单（如"横屏 16:9 → 竖屏 9:16：自动裁剪中心区域 + 字幕上移"）
- 各平台发布规范检查清单

**质量标准**：
- 每个平台必须有独立的发布规范检查清单（分辨率/时长/标签数/CTA 位置）
- 适配动作必须可执行（不能写"优化一下"，要写"使用 ffmpeg crop=1080:1920 裁剪中心区域"）
- 必须标注平台间的发布顺序和时差（避免同一内容在所有平台同时发布，被算法判定搬运）

### Stage 4: 发布排期设计（Publishing Schedule）

**输入**：
- Stage 3 的平台矩阵
- 用户可用的时间/人力资源
- 预算（付费流量）

**输出**：
- 预热期（Day -3 to Day 0）执行清单
- 主发期（Day 1）时间表（精确到小时）
- 长尾期（Day 2-7）互动和数据监控任务
- 复盘期（Day 7+）数据汇总和迭代建议

**质量标准**：
- 时间表必须精确到小时（如"09:00 抖音首发 → 10:00 小红书同步 → 14:00 TikTok 对应时区发布"）
- 必须包含"内容冷却期"规则（同一内容在不同平台间隔 ≥ 1 小时，同一平台不同账号间隔 ≥ 30 分钟）
- 必须预留数据监控和评论回复的人力窗口

### Stage 5: 追踪与结算（Tracking & Settlement）

**输入**：
- 已发布内容的追踪链接/优惠码/UTM 参数
- 平台后台数据（播放量/互动量/转化量）

**输出**：
- 实时追踪看板（YAML/JSON/Markdown 表格）
- ROI 计算报告（投入成本 vs 收益，分平台/分内容/分模式）
- 优胜内容识别和追加投放建议

**质量标准**：
- 追踪看板必须支持手动输入和自动抓取两种模式
- ROI 计算必须区分"内容生产成本"、"分发人力成本"、"付费流量成本"、"平台佣金成本"
- 优胜内容标准必须量化（如"CPS 模式下，单内容 ROI > 3 且转化率 > 2% 判定为优胜"）

### Stage 6: 矩阵放大（Matrix Amplification）

**输入**：
- Stage 5 的优胜内容识别结果
- 可用账号矩阵 / KOL 资源 / 付费流量预算

**输出**：
- 矩阵分发方案（主账号首发 + 子账号搬运/ remix / 二次创作）
- KOL 合作 brief（内容要求/发布时间/结算方式/数据追踪）
- 付费流量加持方案（DOU+/薯条/信息流，预算分配 + 目标人群 + 预期 ROI）

**质量标准**：
- 矩阵分发必须标注"原创"与"搬运/ remix"的区别，避免平台处罚
- KOL brief 必须包含内容要求（可做什么/不可做什么）、发布时间窗口、数据追踪方式、结算触发条件
- 付费流量方案必须给出预算上限、止损条件（如"连续 2 小时 ROI < 1 则暂停投放"）

## 输出结果格式

### 标准交付物

1. **内容资产评估报告**（Markdown）
   - 评分表 + 结论 + 优化建议

2. **分发策略书**（Markdown）
   - 平台矩阵表 + 变现模式选择 + 适配方案

3. **发布排期表**（Markdown / CSV）
   - 预热期/主发期/长尾期/复盘期任务清单

4. **追踪结算模板**（YAML）
   - 内容/平台/时间/数据/收益追踪

5. **矩阵放大方案**（Markdown，可选）
   - 仅当 Stage 1 评分 ≥ 80 且用户有矩阵资源时输出

## 质量检查清单

输出前必须完成以下自检：

- [ ] Stage 1：评分有 5 维度明细，不是只有一个总分
- [ ] Stage 1：评分 < 60 时明确拒绝分发，给出返回上游指令
- [ ] Stage 2：收益预估有公式 + 参数假设 + "预估仅供参考"声明
- [ ] Stage 2：结算模板包含内容 ID、平台、追踪链接、优惠码
- [ ] Stage 3：每个平台有独立的发布规范检查清单
- [ ] Stage 3：适配动作可执行（具体到工具/参数/步骤）
- [ ] Stage 4：时间表精确到小时
- [ ] Stage 4：包含内容冷却期规则（平台间隔 ≥ 1h，同平台账号间隔 ≥ 30min）
- [ ] Stage 5：ROI 计算区分 4 类成本（内容/人力/流量/佣金）
- [ ] Stage 5：优胜内容标准量化（ROI/转化率阈值）
- [ ] Stage 6：矩阵分发标注原创/搬运/remix 区别
- [ ] Stage 6：付费流量方案有预算上限和止损条件
- [ ] 全局：所有追踪链接使用 UTM 参数，可区分平台和内容
- [ ] 全局：所有优惠码唯一且可追溯
- [ ] 全局：输出中包含"本方案基于假设参数，实际收益以平台结算为准"免责声明

## 依赖说明

本 Skill 默认上游为 `product-promo-video-maker`，但设计上保持松耦合：
- 用户直接提供内容资产（视频文件/图文/链接）→ 直接开始 Stage 1
- 用户未提供内容资产 → 提示"请先完成内容生产，推荐使用 product-promo-video-maker Skill"
- 上游 Skill 输出的视频/网页/文案可直接作为本 Skill Stage 1 的输入
