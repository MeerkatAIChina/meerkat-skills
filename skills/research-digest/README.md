# 📊 Research Digest — 把信息洪流压成可行动的研究简报

> **你关注了 37 个 RSS 源、15 个 Newsletter、8 个行业报告渠道——但\"看了\"不等于\"用上了\"。**

信息过载不是问题，信息未加工才是。大多数营销和战略团队花了时间\"保持行业敏感度\"，最后产出的只是一堆存了不看的书签和\"我觉得好像看过一个数据\"的模糊记忆。Research Digest 把信息消费变成**结构化研究产出**：从 RSS/搜索/社区等多源采集 → 来源可信度评分 → 跨源交叉验证 → 提炼可行动的简报——让每一次\"了解行业\"都有产出物、有引用、有对立观点。

---

## 🚧 边界

| ✅ 能做的 | ❌ 不做的 |
|-----------|-----------|
| 从 RSS、网页搜索、行业报告、社区讨论等多源采集 | 不接入付费 API（需要你自己的订阅账号） |
| 四维来源评估（可信度/时效性/相关性/独特性） | 不代替一手调研（用户访谈、问卷） |
| 跨源交叉验证（3+ 来源确认一个发现） | 不做预测性分析（\"X 市场将在明年增长 Y%\"） |
| 自动生成含引用来源的标准化简报 | 不编造数据——缺数据就标注\"数据不足\" |

---

## ⚡ 核心能力

### 🔍 来源评估计分卡

每条来源按四维加权打分：

| 维度 | 权重 | 评分逻辑 |
|------|------|----------|
| 可信度 | 30% | 一手研究 > 分析 > 汇总 > 观点 |
| 时效性 | 25% | 7 天内 > 30 天 > 90 天 > 更早 |
| 相关性 | 25% | 直接相关 > 邻近领域 > 边缘 |
| 独特性 | 20% | 独家数据 > 独特视角 > 常识 |

### 📋 简报结构（标准化输出）

```
研究简报：[主题]
日期：[YYYY-MM-DD]
深度：Quick Scan / Standard / Deep Dive
审查来源数：[N]

→ 执行摘要（3 条关键发现）
→ 核心发现（每条 2-3 段 + 来源引用）
→ 数据点（指标 + 数值 + 来源 + 日期表格）
→ 专家观点（引述 + 姓名/头衔/来源）
→ 对立观点与细微差异（至少 1 条反向视角）
→ 内容角度（如何将此研究用于内容创作）
→ 来源列表（名称 + URL + 可信度评级）
```

### 🎚️ 三种深度

| 深度 | 来源数 | 产出 | 适用 |
|------|--------|------|------|
| Quick | 3-5 源 | 1 页执行摘要 | 快速决策参考 |
| Standard | 8-15 源 | 完整简报 | 周度研究/内容依据 |
| Deep | 20+ 源 | 深度报告 | 战略决策/市场进入 |

## 👤 谁在用

- **产品营销**：为定位和消息策略提供行业依据
- **内容策略**：找到数据驱动的内容角度和有引用的论点
- **创始人**：快速了解一个新市场或品类，不靠\"我觉得\"

---

## 🔗 配合使用

- 竞品分析 → `competitor-profiling` 做竞争对手专项深挖
- 市场研究 → `market-research` 覆盖更广泛的市场结构分析
- 内容创作 → `content-idea-generator` 将研究发现转化为选题
- Reddit 补充 → `reddit-insights` 补充社区端的真实用户声音

**输入**：研究主题 + 时间范围 + 深度要求
**输出**：标准化研究简报（含来源引用和对立观点）
