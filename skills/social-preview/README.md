# 🖼️ Social Preview — 你的 GitHub 仓库在社交网络上长什么样？别让默认灰色方块替你说话

> **你花 200 小时写了一个开源项目，然后有人在 Twitter 上分享它——链接展开，一张灰色默认图。第一印象没了。**

GitHub 仓库被分享到 Twitter、LinkedIn、Slack、Discord 时，那张 1280×640 的 OG 预览图是唯一的视觉触点。没有它，你的项目看起来像未完工的半成品；有一张好的，它能在一秒内告诉别人"这是什么、谁做的、什么语言"。Social Preview 帮你**从零生成这张最高杠杆的视觉资产**——扫描仓库上下文 → 选模板 → 生成 HTML → 导出 PNG → 设置到 GitHub——一条龙搞定。

---

## 🚧 边界

| ✅ 能做的 | ❌ 不做的 |
|-----------|-----------|
| 自动扫描仓库元数据（名称/描述/语言/Logo/Git 远程） | 不修改你的仓库代码 |
| 三种模板（深色/浅色/极简）+ 品牌色适配 | 不做复杂动画或视频预览 |
| 生成纯 HTML（零外部依赖，系统字体，内联 CSS） | 不自动上传（需你手动在 GitHub Settings 上传） |
| 预览图审计（检查是否已设置、尺寸是否正确） | 不做非 GitHub 仓库的 OG 图（那是 image 技能的事） |

---

## ⚡ 核心能力

### 📋 两条命令

```
/social-preview generate [repo-path]   # 生成 OG 预览图
/social-preview audit [repo-path]      # 检查当前预览图状态
```

### 🎨 三种模板

| 模板 | 背景 | 适用 |
|------|------|------|
| **深色**（推荐） | #0d1117 或 #141414 + 浅色文字 | 最高对比度，Twitter/LinkedIn/Slack 表现最佳 |
| **浅色** | #fafbfc + 深色文字 | 匹配特定品牌美学 |
| **极简** | 纯色 + 项目名 + 一句话描述 | 干净、字体导向 |

### 🔧 生成流程（6 步）

1. **扫描**仓库：项目名、描述、主语言、Logo 文件、Git 远程地址、现有预览图状态
2. **选模板**：展示三种方案让用户选择，检测品牌色（从 CSS/Tailwind 配置提取）
3. **生成 HTML**：1280×640 视口，纯系统字体，零外部依赖，内联 CSS
4. **导出 PNG**：三种路径——浏览器截图（零依赖）→ Puppeteer 自动化 → 云端渲染
5. **设置到 GitHub**：UI 上传（推荐）或 API 方式
6. **验证**：提供 Twitter Card Validator / Facebook Sharing Debugger / LinkedIn Post Inspector 链接

### 🎯 设计铁律

- **缩略图可读性优先**——社交信息流显示约 400px 宽，文字必须在该尺寸下清晰
- **两行封顶**：项目名 + 一句话描述，再无其他文字
- **高对比度**：最低 4.5:1 对比度
- **零外部资源**：HTML 渲染时不能有任何网络请求（系统字体、内联 CSS、无外部图片）
- **PNG < 1MB**：避免 JPEG（文字图片的压缩伪影）

## 👤 谁在用

- **开源项目维护者**：新项目发布前、品牌翻新时、大版本发布时刷新预览图
- **DevRel/开发者关系**：确保组织下所有仓库都有统一的品牌预览
- **技术创始人**：个人项目也需要看起来专业

---

## 🔗 配合使用

- 仓库健康 → `repo-health` 审计仓库整体状态（包括预览图是否缺失）
- GitHub README → `github-readme` 确保 README 和预览图品牌一致
- 图片技能 → `image` 处理非 GitHub 场景的 OG 图和社交图片
- 品牌 DNA → `brand-dna` 确保仓库视觉与品牌体系对齐

**输入**：Git 仓库路径（默认当前目录）
**输出**：HTML 模板文件 + PNG 预览图 + 设置指引 + 验证链接
