# 🗺️ 客户旅程地图（Customer Journey Mapping）

> **用户来了，转了一圈，然后默默走了。你不知道他们卡在哪——因为你看不到完整的旅程。**

你盯着 GA4 的漏斗图，转化率在某个节点断崖式下降，但数字不会告诉你"为什么"。用户在哪个触点开始焦虑？在哪一步失去信心？从"没听说过你"到"推荐给别人"，中间有几十个隐形裂谷——漏掉任何一个，前面的获客投入都在为后面的流失买单。

---

## 🚧 边界：我们能做什么，不做什么

| ✅ 能做的 | ❌ 不做的 |
|-----------|-----------|
| 绘制 6 阶段完整旅程地图 | 不替代 GA4 等数据分析工具 |
| 标记每个阶段的情绪/痛点/机会 | 不编造你没有数据的旅程节点 |
| 按角色/规模/意图差异化建模 | 不把所有用户塞进同一条路径 |

---

## ⚡ 核心能力

1. **六阶段旅程** —— 认知 → 考量 → 决策 → 上线 → 留存 → 推荐，每阶段定义客户目标、情绪状态、触点、流失风险
2. **触点清单** —— B2B SaaS 常见触点（Google 搜索→博客→Demo→销售演示→欢迎邮件→QBR→NPS…）全部预置
3. **流失诊断** —— 每个阶段过渡处标注常见流失原因和具体修复方案
4. **角色分流** —— 技术评估者 vs 高管 vs 终端用户，B2B 自服务 vs 销售驱动，走完全不同的旅程

---

## 👤 谁在用

- **客户成功团队**：找到上线到留存的断点
- **市场/增长团队**：定位漏斗中最值得优化的环节
- **产品团队**：理解功能与体验之间的落差

---

## 🔗 配合使用

- 需要漏斗数据 → 接入 `google-analytics` 拉实际转化路径
- 发现高流失页面 → 调用 `cro-auditor` 深入优化
- 留存/推荐阶段问题 → 调用 `churn-prevention` 做挽回策略
- 需要做角色分流 → 先用 `icp-research` 定义不同画像

**输入**：产品类型 + 目标客群
**输出**：可视化旅程地图 + 每个阶段痛点/机会/指标 + 流失修复建议
