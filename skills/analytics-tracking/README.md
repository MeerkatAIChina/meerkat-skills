# Analytics Tracking — 数据埋点与追踪体系搭建

> **让每一个事件都回答一个商业问题，而不是制造一个数字。**

---

## 你的追踪是在"造船"还是在"打渔"？

大多数团队的"数据追踪"现状：GA4 装上了，GTM 配上了，UTM 参数也加了——但三个月后打开报表，依然不知道钱花在哪里有效。问题不在工具，在**追踪体系缺失**。

Analytics Tracking 是数据驱动营销的"基础设施工程"技能。它不教你点按钮，而是帮你回答三个根本问题：

- **我们到底该追踪什么？**（从商业决策倒推事件清单，拒绝虚荣指标）
- **怎么追得干净？**（命名规范、属性设计、隐私合规一步到位）
- **出问题了怎么查？**（DebugView + Preview Mode + Network Tab 三件套排查）

## 这套方法论的核心信条

### 1. 为决策追踪，不为数据量追踪

你的 GA4 里可能有 200 个事件——但真正帮你做出决策的有几个？每个事件上线前，问自己：**如果这个数字涨了 20%，我会做什么？** 答不上来的，是在收集噪音。

### 2. 先定义问题，再设计事件

"我们想知道用户行为"不是问题。"我们想知道为什么定价页的跳出率比行业基准高 40%，以及从哪些渠道来的用户最有付费意愿"才是问题。从问题出发，事件清单会短 70%，但价值高 10 倍。

### 3. 命名即文档

`button_clicked` 和 `cta_hero_clicked` —— 前者两个月后没人记得是什么按钮，后者自带上下文。对象-动作命名法（Object-Action）+ 下划线小写 + 上下文放属性而非事件名，是团队协作的生命线。

### 4. 脏数据 > 没有数据

Duplicate events、undefined 属性值、PII 泄露——这些问题比装上 GA4 本身重要一百倍。追踪部署的"最后一公里"是验证，不是部署。

## 谁需要这个技能？

- **产品营销经理**负责网站但不知道前端怎么埋点的
- **增长负责人**要建从广告点击到付费的全链路归因
- **技术 SEO** 需要把页面性能数据关联到转化数据
- **代理机构交付团队**需为客户输出标准化追踪方案的
- **任何问了"这东西怎么衡量"的人**

## 关联生态

| 下游技能 | 关系 |
|----------|------|
| **Google Analytics** | Analytics Tracking 把数据送进 GA4，GA4 负责分析 |
| **Google Tag Manager** | GTM 是追踪落地的执行层，这个技能是规划层 |
| **UTM Attribution Strategy** | UTM 参数体系是追踪方案中的"流量标签子系统" |
| **Looker Studio** | 追踪数据 → 可视化呈现，形成完整数据闭环 |
| **RevOps** | 营销追踪延伸到 CRM，连接市场到营收 |
