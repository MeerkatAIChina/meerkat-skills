# GitHub README Generator — 让你的开源项目第一印象拉满

> 一个糟糕的 README 能让优秀代码瞬间贬值。一个专业的 README 能让 side project 看起来像有团队在维护。

## 痛点：README 不是"有就行"

大多数开发者的 README 只有两种形态：要么是从脚手架生成的一言半语，要么是需求文档复制粘贴出来的巨幅长文。更致命的是——API 密钥泄露在代码示例里、内部主机名暴露在安装步骤中、版本号五年没更新……这些看似微小的疏忽，在公开仓库里就是安全风险与信任杀手。

## 能力：三种模式覆盖 README 全生命周期

`github-readme` 不是模板生成器，它是**仓库感知型文档引擎**。它会先扫描你的目录结构、技术栈、Git 配置、已有文档，然后自动识别项目类型（CLI 工具 / 库 SDK / 集合市场 / Web 应用 / 个人实验），为每种类型匹配最合适的章节结构。

三种模式随心切换：

- **`generate`** — 从零生成：自动检测技术栈、定制 Badge、校准语调，一次性输出即可发布的 README。
- **`audit`** — 只读评分：从清晰度、可用性、可信度、时效性和安全性五个维度打分（0-100），仅暴露问题不改任何代码。
- **`update`** — 增量更新：发现过期版本号、缺失章节、安全泄露，生成 diff 式修改计划，经你确认后再执行。

每一次操作都内置了 **PII/基础设施清洗**——私有 IP、内部主机名、API 密钥、个人邮箱……该改的改，该删的删，绝不商量。

## 谁在用？

- **独立开发者**：准备开源 side project，需要一个"不像 side project"的门面。
- **开源维护者**：定期审计 README 质量，保持社区信任。
- **技术团队负责人**：接手新仓库时快速评估文档健康度。
- **DevRel / 布道师**：发布前的最后一关，确保公开信息无安全风险。

## 配合其他技能

- **`repo-health`**：先跑全面健康检查，再用本技能针对性优化 README。
- **`repo-scaffold`**：新仓库搭建完基础文件后，一把生成配套 README。
- **`safe-push`**：README 更新完，推送到公开仓库前做最终安全扫描。
- **`llms-txt`**：为项目生成 llms.txt，提升 AI 搜索可发现性。

> **"README 是你开源项目的面孔。大多数开发者花 50 小时写代码，花 5 分钟写 README。这个比例应该倒过来。"**
