# 🚀 GitHub README 生成器 — 让你的开源项目「开口说话」

> **README 是你的项目在 GitHub 上的唯一销售页。它要么在 15 秒内抓住开发者的注意力，要么让他们关掉标签页。**

---

## 你正面临的痛点

你花了几百个小时写代码，开源了一个项目，但 README 只有三行字、没有安装说明、没有 Badge——甚至还有 API Key 暴露在上面。**糟糕的 README 不是文档问题，是增长问题。** 开发者看一眼就跑，Star 停止增长，招聘时候选人看不懂你们在做什么。

**更隐蔽的损失**：你的项目在搜索引擎和 AI 工具（ChatGPT / Claude / Perplexity）中完全不可见——因为你的 README 没有做任何 SEO/AEO 优化。

---

## 这个 Skill 能做什么

| ✅ 能做 | ❌ 不做 |
|---------|---------|
| 自动扫描仓库结构，识别项目类型（CLI/库/Web应用/集合） | 不会编造你没写的功能 |
| 生成结构完整、语气专业、Badge 齐全的 README | 不会写产品营销文案（那是 copywriting Skill 的事） |
| 对已有 README 进行 0-100 分质量审计（清晰度/可用性/可信度/时效性/安全性） | 不会修改你的代码或仓库配置 |
| 检测并自动删除 PII/密钥/内网 IP 等安全隐患 | 不会在 audit 模式下改动任何文件 |
| 提供 GitHub 搜索可见度优化建议（仓库名/描述/Topics/社交预览图） | 不会替代 SECURITY.md 或 CONTRIBUTING.md 的详细内容 |

## 核心能力

| 能力 | 说明 |
|------|------|
| **三模式操作** | `generate` 从零生成 / `audit` 只读打分 / `update` 增量修补 |
| **项目类型感知** | 自动识别 CLI 工具、库/SDK、集合市场、Web 应用、个人实验项目 |
| **声音校准** | 5 种默认语气——直接实用/技术精准/可扫描/产品清晰/第一人称 |
| **智能 Badge** | 根据检测到的技术栈自动生成，style=for-the-badge，排版有序 |
| **安全擦洗** | 扫描并自动移除密钥、Token、内网 IP、私有主机名、个人邮箱 |
| **SEO/AEO 建议** | 仓库名关键词检查 + GitHub Topics 推荐 + llms.txt 生成建议 |

### 质量审计五维评分体系
- **清晰度 (25%)** — 一句话描述是否到位？标题是否具描述性？
- **可用性 (25%)** — 安装命令可运行吗？有代码示例吗？上手步骤 ≤20 行？
- **可信度 (15%)** — Badge 存在且可解析吗？License 声明到位吗？
- **时效性 (15%)** — 版本号与实际配置一致吗？技术栈描述匹配吗？链接不失效？
- **安全性 (20%)** — 无 PII 泄露？无密钥/Token 暴露？无私有主机名/IP？

## 谁应该用

- ✅ 开源项目维护者——README 是项目增长的起点
- ✅ 开发者工具/DevTools 公司的市场人员——这是你最重要的产品页面
- ✅ 技术创始人——准备把你的 side project 公开，需要一份体面的 README
- ✅ CTO/技术负责人——公司仓库的 README 是招聘漏斗的第一环
- ✅ 开源社区运营——管理多仓库的 README 质量一致性
