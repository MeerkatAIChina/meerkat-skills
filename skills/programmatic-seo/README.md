# Programmatic SEO — 不做 100 页内容，做 10000 页

> **你的竞品为什么有几千个页面挂在搜索引擎里吃流量？不是他们团队有一百个写手——是他们会用数据生页面。**

---

## 一、手工做内容就像手工耕地

一篇一篇写，一个月出二十篇，一年才两百篇。而你的竞争对手用同一套模板、灌不同数据，一个月上线五千页，每页精准命中一个长尾关键词。

这就是 Programmatic SEO（pSEO）——**不是 AI 垃圾场的代名词，而是用结构化数据 + 模板引擎批量构建有价值页面的方法论**。Zapier 用"App A + App B 集成"吃下 25000+ 页面，Wise 用"货币 A 兑货币 B"覆盖全球汇率查询——他们不是每页都手写，但每页都有独特数据价值。

---

## 二、先搞清楚：这个 Skill 不是什么

| ❌ 不是 | ✅ 正确选择 |
|---------|------------|
| 一键生成垃圾页面 | 它要求每页至少有 3-5 条独特数据 + 唯一开篇 + 差异化价值 |
| 替代内容创作 | 模板 + 数据填充，不适合深度观点型内容 |
| Google 不惩罚的保票 | 遵循质量原则可以，低质薄内容一样会被打击 |
| 只管页面生成 | 涵盖模板设计、数据源、内链架构、索引管理全流程 |
| 适合所有内容类型 | 适合结构化数据驱动的页型（集成、对比、工具、定义等） |

## 三、真实场景演示

**场景**：一个 HR SaaS 产品想覆盖"[城市] 招聘外包公司"这类长尾关键词，全国 300 个城市。

**`programmatic-seo` 会怎么做？**

```
1. 确定模板结构：
   每个城市页面 = 唯一城市数据 + 固定模板框架

2. 页面模板：
   H1: [城市]招聘外包服务 — 2026 年企业指南
   开篇: [城市]拥有 [X] 万家企业……独特数据 2-3 句
   数据区: 该城市的人力成本 / 社保基数 / 平均招聘周期
   对比区: [城市] vs [邻城] 招聘成本对比
   FAQ: 3-5 个城市定制问答
   内链: 链接到相邻城市页 + 全国总览 Hub

3. 内链架构（Hub & Spoke）：
   Hub (全国招聘外包总览)
   ├── 北京 → 链接回 Hub + 上海/广州/深圳
   ├── 上海 → 链接回 Hub + 北京/杭州/南京
   └── ...

4. 质量底线（Google 不惩罚的前提）：
   → 每页唯一 Title、唯一 Meta、唯一开篇 2-3 句
   → 每页至少 3 条城市专属数据
   → 不跨城市复用正文段落
   → 所有页面有 Schema 标记
   → Sitemap 实时更新，索引率监控

5. 技术实现建议：
   300 页 → SSG（Next.js/Astro）一次性构建
   > 10000 页 → ISR 按需生成 + 分片 Sitemap
```

## 四、核心能力矩阵

| 能力 | 说明 |
|------|------|
| **模板设计** | 输出包含 H1/开篇/数据区/对比区/FAQ/CTA 的完整模板 |
| **数据源规划** | 根据页面类型确定需要什么数据，数据从哪来 |
| **内链架构** | Hub & Spoke 模型：每页链接到 Hub + 3-5 个相关页面 |
| **索引管理** | Sitemap 生成策略、爬取预算分配、Index Coverage 监控 |
| **质量红线** | 每页的最小独特内容量、防重复机制、反模式清单 |
| **技术选型** | SSG/ISR/SSR/CMS 方案选择，按页面量级推荐 |
| **场景适配** | 集成页、城市页、对比页、定义页、工具页、统计页 |

## 五、谁应该用

- ✅ **SaaS 产品市场负责人**：用集成/对比/替代品页面吃长尾搜索
- ✅ **有数据资产的企业**：行业数据库、价格库、城市数据 → 变成页面
- ✅ **SEO 负责人**：手动做内容覆盖不了几百个长尾词
- ✅ **内容团队扩张受阻**：写手不够，但业务需要大量页面覆盖
