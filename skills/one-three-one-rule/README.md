# 🎯 1-3-1 决策沟通框架 — 把「你觉得呢」变成「我建议这么干」

> **开会两小时、Slack 吵了三天、方案换了五版——所有低效决策的根源不是「信息不够」，而是「没有结构」。1-3-1 规则是你在任何决策场景下的结构化表达利器。**

---

## 你正面临的痛点

市场团队每天都在做选择：这个 Campaign 用 Google Ads 还是 Meta？内容策略走 SEO 还是社交媒体？定价是 Freemium 还是一口价？代理商用 A 方案还是 B 方案？

大多数团队的讨论方式是：A 说了一堆、B 反驳一堆、C 提出了一个新的想法——然后会议结束，什么决定都没做。下周再来一轮。

**更糟糕的是向老板/客户汇报**：你拿着一堆数据和想法，但没有一个清晰的结构来说「问题是什么、有哪些选择、我建议选哪一个」。决策者需要你给出判断，不是更多信息。

---

## 这个 Skill 能做什么

| ✅ 能做 | ❌ 不做 |
|---------|---------|
| 把任何复杂决策压缩为五个段落：问题 → 三个选项 → 推荐 → 完成标准 → 执行计划 | 不会替你做决策——最终选择权永远在你 |
| 确保每个选项都是「不同的策略」，而非同一策略的微调 | 不会对一个有唯一正确答案的问题强行给出三个选项 |
| 提供可验证的 Definition of Done——不是「大概做好了」，而是「具体到可以测试的状态」 | 不会在简单的对错问题上使用——那是滥用 |
| 当你选了不同选项时，自动调整推荐理由、完成标准、和行动计划 | 不会输出模糊的实现路径 |

---

## 核心能力

| 能力 | 说明 |
|------|------|
| **1 个问题** | 用一句话锁定核心决策——聚焦「做什么」而非「怎么做」 |
| **3 个选项** | 三个本质不同的可行方案（A/B/C），各有优缺点 |
| **1 个推荐** | 直接给出你的专业判断和理由，不模棱两可 |
| **Definition of Done** | 选定方案的成功标准——具体、可验证、不是口号 |
| **Implementation Plan** | 从第一步到最后一步的执行清单，含具体命令和行动 |

### 适用场景

这个框架不只用于技术决策。在营销场景中，1-3-1 同样强力：

| 场景 | 示例 |
|------|------|
| **广告投放** | "我们该把 20 万预算投哪个渠道？"→ Google Ads / Meta / TikTok 三选一 |
| **内容策略** | "下季度内容重心放哪里？"→ SEO 长文 / 社交媒体短内容 / 视频 |
| **定价决策** | "新功能怎么定价？"→ 含在基础版 / 独立订阅 / 按用量计费 |
| **工具选型** | "用哪个邮件营销平台？"→ Klaviyo / Mailchimp / 自建 |
| **客户提案** | 向客户呈现方案时，用 1-3-1 结构替代散乱的 PPT |

---

## 谁应该用

- ✅ 市场总监/CMO——向 CEO 汇报策略选择，让对方快速做出决定
- ✅ 营销团队 Lead——团队内部讨论方案，避免无限循环的会议
- ✅ 咨询顾问——给客户的提案必须结构清晰、推荐果断
- ✅ 产品营销经理——Go-to-Market 方案需要多路径对比
- ✅ 任何需要做决策并把决策「卖出去」的人
