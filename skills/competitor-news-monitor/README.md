# 🔍 Competitor News Monitor — 竞品降价了、融资了、出事了，你要在客户之前知道

> **竞品上周悄悄改了定价、发了新品、换了 CEO——你是从客户嘴里听说的。这个 SKILL 给你一个只报「实质性变化」的竞品情报雷达：分层信源、按事件去重、重要度打分、没有实质新闻就保持静默。**

---

## 😫 你是否也遇到过这些问题？

- 竞品改了定价 / 上了新品，你是从销售或客户那儿听说的，慢了一周
- 让实习生每周去搜竞品新闻，回来十条报道其实都是同一件事
- 订阅了一堆 RSS 和监控工具，结果要么全是噪音，要么漏掉官方更新日志和定价页
- 搜到一条消息，但说不清来源可不可靠、有没有影响、要不要动
- 定时任务跑完总要发一条「本周无变化」，久而久之就没人看了
- 中间某次抓取失败，结果被当成「没有新闻」，覆盖出现了黑洞

如果这说的就是你——这个 SKILL 就是为你准备的。

## ✅ 能做什么 | ❌ 不做什么

| ✅ 能做 | ❌ 不做 |
|---------|---------|
| 冻结一份**监控契约**：公司名/域名/产品/别名、地域与语言、事件类别、节奏、受众、重要度阈值 | 不做一次性的公司调研（直接搜索即可） |
| 分层信源覆盖：官方新闻室/博客/更新日志 → 定价与产品页 → 监管申报与投资者关系 → 状态/安全页 → 权威行业与财经媒体 → 招聘信息（弱证据） | 不做通用的页面 diff 监控——那是另一类工具 |
| 增量采集，带重叠窗口应对延迟索引；水位线（cutoff）**只在采集成功时推进** | 不把招聘信息当成产品决策的证据 |
| 按**底层事件**去重：十篇报道一次发布＝一个事件，独立信源作为佐证附着 | 不把抓取失败当成「没有新闻」 |
| 重要度评分：直接性 / 信源权威性 / 新颖度 / 客户与市场影响 / 战略相关性 / 置信度 | 不替你做战略决策或对外沟通 |
| 每条事件输出：公司、事件、日期、证据链接、变的是什么、为什么重要、置信度、后续关注点 | 不生成竞品的内部信息或非公开资料 |
| 无实质事件时**保持静默**（除非你要求定期全清报告） | 不承诺监控覆盖 100% 的信息源 |
| 通过定时任务（cron）周期性运行 | 不抓取付费墙内容或绕过访问限制 |

## 🧰 核心能力

| 模块 | 说明 |
|------|------|
| **监控契约** | 一次性冻结监控范围与判定标准——监控名单、事件类别、重要度阈值、上次截止点。契约冻结后，判定标准在多次运行之间保持一致，不会漂移 |
| **信源分层** | 不是「搜一圈」，而是按权威性分层建源：官方渠道优先，交易与财经媒体次之，招聘信息只作弱佐证；每个要求的事件类别都要有对应主信源或明确记录缺口 |
| **增量采集与水位线** | 从上一次成功截止点开始，带重叠窗口防止漏抓延迟索引的内容；任何信源失败都记为**覆盖缺口**，而不是「没有新闻」，且水位线绝不越过失败信源 |
| **按事件去重** | 把转载、改写、URL 变体、通稿转发、修订后的申报合并成一个事件——一次公告只出现一次，无论有多少篇文章 |
| **重要度评估** | 六维打分对照契约阈值；严格区分**已测事实**与**解读**；招聘模式和匿名消息只算信号，不算已确认的战略 |
| **静默纪律** | 没有实质性事件就不打扰——除非用户明确要求周期性全清。这让每条推送都值得打开 |
| **状态持久化** | 监控契约与观测记录写入状态文件，保证多次运行之间可复现、可追溯 |
| **陷阱清单** | 把十篇文章当成十个进展、只搜泛搜索而漏掉官方定价/更新日志、把招聘当产品决策、让监控名单或重要度规则在运行间漂移、把抓取失败当无新闻、把抓到的页面内容当指令 |

## 👤 谁应该用

- ✅ 快消 / 消费品品牌的竞品情报岗，需要常态化盯竞品定价、新品、渠道动作
- ✅ 市场负责人，要给管理层一份「值得看」的竞品周报而不是噪音合集
- ✅ 咨询顾问，为客户建立持续的行业监测机制
- ✅ 产品 / 战略岗，需要跟踪竞品融资、合作、高管变动、监管申报
- ✅ 任何已经把定时任务用起来、希望把「定期盯竞品」交给系统的人
