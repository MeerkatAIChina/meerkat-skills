# Technical SEO Audit — 搜索引擎能不能"看懂"你的网站？我们来测

> **你的内容不差、关键词也对，但 Google 就是不收录、不排名。问题可能不在内容——在基础架构。**

---

## 一、"我的 SEO 没问题"——你确定吗？

太多网站把 SEO 等同于"文章里多放几个关键词"。但在此之前，有个更基础的问题：**搜索引擎到底能不能正常抓取、渲染、理解你的网站？**

如果 robots.txt 把核心目录封了，如果 Sitemap 里全是 404，如果页面加载要 8 秒——你的内容写得再好，搜索引擎也看不到。`technical-seo-audit` 不关心你的内容好不好，它只追问一个核心问题：**你的技术地基牢不牢？**

## 三、真实场景演示

**场景**：一个电商网站新上了 5000 个产品页，但 Search Console 显示只索引了 200 个。

**`technical-seo-audit` 会怎么做？**

```
Phase 1: 爬取与索引
├── robots.txt → 正常，无封锁
├── XML Sitemap → 发现：Sitemap 包含 5000 个 URL，但其中 1200 个返回 301
│   （CMS 自动生成的规范链接不一致）
└── 诊断：Google 遇到 301 会浪费爬取预算，
    真正需要索引的页面被淹没

Phase 2: 架构与内链
├── 爬取深度 → 产品页在 4-5 层深，超过 3 层阈值
├── 孤岛页面 → 新增的 300 个产品页零内链
└── 修复建议 → 在分类页增加产品列表，缩短爬取路径

Phase 3: 性能
├── LCP: 4.2s → 主因：产品图未压缩 + 无 CDN
├── CLS: 0.18 → 主因：首屏动态注入横幅广告
└── 修复建议 → 图片 WebP + lazy load + 预留广告位尺寸

输出分级：
🔴 紧急 → Sitemap 301 污染，索引率仅 4%
🟠 高优 → LCP > 4s，影响排名和用户体验
🟡 中优 → 孤岛页面 + 爬取深度问题
```

## 四、核心能力矩阵

| 审计阶段 | 核心检查 | 典型发现 |
|---------|---------|---------|
| **爬取** | robots.txt、Sitemap 健康、爬取预算 | Sitemap 含死链、爬取陷阱（无限分页） |
| **索引** | Index/Noindex、Canonical 链、软 404 | 重要页面误标 Noindex、Canonical 链过长 |
| **架构** | URL 结构、内链分布、面包屑 | 重要页面 4+ 层深、锚文本过度优化 |
| **性能** | LCP/INP/CLS、资源加载、缓存策略 | 字体的 CLS、未预加载的英雄图 |
| **页面元素** | Meta 标签、Heading 层级、Schema 验证 | 多 H1、Heading 跳级、Schema 缺失必填字段 |
| **安全** | HTTPS、HSTS、混合内容、安全头 | 部分资源 HTTP、证书即将过期 |
| **国际化** | Hreflang、多语言 Sitemap、Canonical 一致性 | 缺 return tag、跨语言错用 Canonical |
| **移动端** | 移动优先适配、触摸目标、3G 速度 | 桌面和移动内容不一、字体过小 |
