# 🛡️ Churn Prevention — 流失预防与用户留存体系

**一句话说清楚**：用户不会无缘无故离开。Churn Prevention 帮你从取消流程设计、动态挽留方案、支付失败追回三个维度，系统化地降低自愿流失和非自愿流失 — 守住你的 MRR。

## 流失的两种面孔，两种解法

| 类型 | 占比 | 原因 | 解法 |
|------|------|------|------|
| **自愿流失** | 50-70% | 用户主动取消 | 取消流程、挽留方案、退出调查 |
| **非自愿流失** | 30-50% | 支付失败 | 催款邮件、智能重试、卡片更新 |

大多数团队只关注自愿流失（"用户为什么要走？"），却忽略了非自愿流失 —— 而这恰恰是**最容易修复**的流失类型。支付失败导致的沉默取消，只要搭建一套基础的催款流程，通常可以挽回 40-60%。

## 核心能力一：取消流程设计

每一个取消流程都应该遵循这个结构：

```
用户点击"取消订阅" → 退出调查 → 动态挽留方案 → 确认取消 → 取消后体验
```

### 退出调查：挽留策略的基础

不要一上来就甩优惠券。先问清楚用户为什么走。好的退订原因分类：

| 原因 | 用户真正的问题 | 匹配方案 |
|------|--------------|---------|
| 太贵了 | 价格敏感 | 20-30% 折扣（2-3 个月）或降级 |
| 用得不多 | 低参与度 | 暂停订阅（1-3 个月）或免费上手指导 |
| 缺少某个功能 | 产品缺口 | 路线图预览 + 上线时间表 |
| 切换到竞品 | 竞争压力 | 竞品对比 + 折扣 |
| 技术问题/Bug | 产品质量 | 立即升级到客服 + 补偿 |
| 临时/季节性 | 使用模式 | 暂停订阅 |

**核心洞察**：挽留方案必须与取消原因匹配。给一个"不怎么用你产品"的人发折扣券毫无意义 — 他需要的是暂停或上手帮助。给一个"买不起"的人看产品路线图也是浪费 — 他需要的是降级或折扣。

### 挽留方案类型全览

| 方案类型 | 最佳参数 | 注意 |
|---------|---------|------|
| **折扣** | 20-30% 减 2-3 个月 | 避免 50%+ 深度折扣（培养"取消换优惠"行为） |
| **暂停** | 1-3 个月 | 60-80% 的暂停用户最终回归，超过 3 个月很少激活 |
| **降级** | 推荐低一档套餐 | 定位为"为你匹配合适方案"而非"降级" |
| **功能解锁** | 解锁未试用过的高级功能 | 最适合"没得到足够价值"的场景 |
| **人工触达** | 针对 Top 10-20% MRR 的高价值账户 | 转接客户成功或创始人亲笔邮件 |

## 核心能力二：流失预测与主动留存

最好的挽留发生在用户点击"取消"之前。

### 流失预警信号

| 信号 | 风险等级 | 距取消时间窗口 |
|------|---------|--------------|
| 登录频率下降 50%+ | 高 | 2-4 周 |
| 核心功能使用停止 | 高 | 1-3 周 |
| 客服工单激增后骤停 | 高 | 1-2 周 |
| 账单页面访问激增 | 高 | 几天内 |
| 团队成员席位减少 | 高 | 1-2 周 |
| 数据导出触发 | 极危 | 几天内 |
| NPS 评分 < 6 | 中 | 1-3 个月 |

### 健康度评分模型

```
健康分 = 
  登录频率分 × 0.30 +
  功能使用分   × 0.25 +
  客服情感分   × 0.15 +
  账单健康分   × 0.15 +
  参与度分     × 0.15
```

| 分数 | 状态 | 行动 |
|------|------|------|
| 80-100 | 健康 | 向上销售机会 |
| 60-79 | 需关注 | 主动关怀 |
| 40-59 | 风险 | 干预 Campaign |
| 0-39 | 危急 | 个人一对一触达 |

## 核心能力三：支付失败追回（催款体系）

```
预催款 → 智能重试 → 催款邮件序列 → 宽限期 → 硬取消
```

### 智能重试策略

| 失败类型 | 示例 | 重试策略 |
|---------|------|---------|
| 软失败（临时） | 余额不足、通道超时 | 7-10 天内重试 3-5 次 |
| 硬失败（永久） | 卡被盗、账户关闭 | 不重试 — 直接要求换卡 |
| 需认证 | 3D Secure、SCA | 引导用户更新支付方式 |

**重试节奏**：失败后 1 天 → 3 天 → 5 天 → 7 天（随催款邮件逐级升级）

### 催款邮件序列

| 邮件 | 时机 | 语气 | 内容 |
|------|------|------|------|
| 第 1 封 | 失败当天 | 友好提醒 | "付款未成功，请更新卡片" |
| 第 2 封 | 第 3 天 | 帮助性提醒 | "快速提醒 — 更新付款方式以保持访问" |
| 第 3 封 | 第 7 天 | 紧迫感 | "账户将在 3 天后暂停。现在更新" |
| 第 4 封 | 第 10 天 | 最后警告 | "保留账户的最后机会" |

### 恢复率基准

| 指标 | 差 | 平均 | 好 |
|------|---|------|---|
| 软失败恢复 | <40% | 50-60% | 70%+ |
| 硬失败恢复 | <10% | 20-30% | 40%+ |
| 总体支付恢复 | <30% | 40-50% | 60%+ |

## 常见误区

- **没有取消流程** — 直接取消等于丢钱。哪怕一个简单的调查+一个挽留方案就能拯救 10-15%
- **隐藏取消按钮** — 这招在多地已经违法（FTC Click-to-Cancel 规则），且会激发差评
- **无论什么理由都甩折扣** — 对"缺功能"的用户发优惠券是浪费
- **折扣太深** — 50%+ 折扣培养"取消拿优惠"循环
- **忽略非自愿流失** — 支付失败造成的流失常常占 30-50%，且最容易修复
- **没有挽留方案 LTV 追踪** — 被"救回来"但 30 天后又流失的用户并不算真正被救回

## 适合谁用？

- SaaS 月度流失率高于预期的产品或增长团队
- 正在搭建或优化取消流程的 B2B/B2C 订阅业务
- 支付失败率偏高但尚未建立催款体系的财务/运营团队
- 想建立主动流失预警和健康度评分的客户成功团队

> ⚠️ 注意：本技能中挽留率、恢复率等数据基于公开 SaaS 行业研究和方法论框架。实际效果取决于定价、产品品类、用户画像等多因素。具体挽留方案的 A/B 测试建议使用 ab-test-setup 技能进行科学验证。
