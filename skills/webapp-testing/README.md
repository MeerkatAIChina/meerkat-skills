# 🧪 Web 应用测试工具包 — 让你的营销站点不出 Bug

> **一句话：用 Playwright 自动化测试你的落地页、注册流程、表单提交——在用户发现 Bug 之前修掉它。**

---

## 🤔 你的营销站点上线前，最后一次完整测试是什么时候？

- 「按钮在 Chrome 上能点，但 Safari 用户反馈点不了……」
- 「改了注册流程，结果移动端表单提交失败，丢了几十个线索才发现」
- 「每次上线都靠手动点点点，测完桌面端就懒得测移动端了」
- 「A/B 测试页面上了，但根本没验证过不同版本在 320px 屏幕上的表现」

**Web 应用测试工具包**给你一套开箱即用的 Playwright 自动化测试脚本——静态 HTML 分析、动态页面截图、浏览器日志捕获，把你的营销站点 QA 从「靠运气」变成「靠工具」。

---

## 🎯 边界说明

| ✅ 能做什么 | ❌ 不做什么 |
|-----------|-----------|
| 自动化测试本地运行的 Web 应用（前端项目） | 不测试已部署到生产环境的站点（那是监控范畴） |
| 静态 HTML 直接解析，动态页面等待 networkidle 后检查 | 不替代完整的 E2E 测试框架（Cypress/Playwright Test Runner） |
| 截图捕获：全页面、指定元素、不同视口 | 不执行性能测试（Lighthouse/WebPageTest 请另用） |
| 浏览器控制台日志捕获 | 不测试后端 API（Postman/curl 请另用） |
| 管理服务器生命周期（启动/停止前后端服务） | 不管理生产服务器 |
| 多服务器场景支持（前端+后端同时起） | — |

---

## 🧰 核心能力

| 能力 | 说明 |
|------|------|
| **静态页面分析** | 读取 HTML 直接识别选择器，快速验证静态页面结构 |
| **动态页面侦察** | 等待 networkidle 后截图+检查 DOM，处理 JS 渲染的页面 |
| **服务器管理** | `with_server.py` 脚本自动启动/停止测试服务器，支持单服务和多服务 |
| **选择器发现** | 自动识别页面上的按钮、链接、输入框等元素 |
| **控制台日志** | 捕获浏览器 console 输出，追踪 JS 错误和警告 |
| **无头浏览器** | Chromium 无头模式运行，不依赖 GUI |
| **黑盒脚本** | 预置脚本直接调用，不污染上下文窗口 |

## 👤 谁应该用

- ✅ 增长工程师——A/B 测试页面变体上线前需要验证
- ✅ 前端开发者——做营销站点，需要快速 QA 工具
- ✅ CRO 专家——验证不同版本的注册流程/表单在各种设备上的表现
- ✅ 产品营销经理——产品发布前确认 Landing Page 在各浏览器上正常
- ✅ 创业者——没有 QA 团队，但需要确保站点质量

## 🔗 配合其他 SKILL

| 搭配 SKILL | 联动场景 |
|-----------|---------|
| `landing-page-optimizer` | 优化完落地页后，用 testing 验证改动在真实浏览器中的表现 |
| `signup-flow-cro` | 改了注册流程后用 testing 自动验证流程完整性 |
| `form-cro` | 表单优化后验证提交功能、字段校验、移动端适配 |
| `page-cro` | 页面改动后在多尺寸下截图对比 |
| `popup-cro` | 弹窗触发逻辑需要在不同条件下验证 |
| `frontend-design` | 新设计的页面在发布前用 testing 过一遍浏览器兼容 |
| `ab-test-setup` | A/B 测试变体上线前做功能验证 |
