# 制造业价值链定位框架

## 目的与使用方式
本文件用于将具体场景定位到制造业全价值链（研、产、供、销、服），并识别上下游依赖关系，避免只盯住单点工序而忽略全链路协同。

**核心原则**：
- 优先按"业务影响"定位，而不是按组织架构定位
- 必须识别上下游依赖关系，形成链路思维
- 如果场景横跨多个链条，确定主环节和协同环节
- 必须明确输入来源和输出去向

---

## 五大主价值链

### 研（研发与工艺）

| 维度 | 内容 |
|------|------|
| **核心目标** | 定义产品与工艺能力，确保设计可制造、工艺可执行 |
| **典型场景** | 需求分析、设计开发、试产导入、工艺验证、ECN 变更、DFMEA |
| **上游输入** | 客户需求、技术规范、历史问题、竞品信息 |
| **下游输出** | 图纸、BOM、工艺路线、参数标准、检验标准 |
| **关键角色** | 产品经理、研发工程师、工艺工程师、质量工程师 |
| **AI 提效机会** | 设计规则校验、相似方案推荐、DFMEA 辅助、变更影响分析 |

### 产（生产制造）

| 维度 | 内容 |
|------|------|
| **核心目标** | 稳定、高效、可追溯地完成制造，确保质量、成本、交期 |
| **典型场景** | 排产、派工、换线换模、装配、测试、质检、包装、设备维护 |
| **上游输入** | 订单、工单、物料、工艺文件、设备状态 |
| **下游输出** | 合格品、过程数据、质量记录、追溯信息 |
| **关键角色** | 计划主管、班组长、操作员、设备工程师、质量工程师 |
| **AI 提效机会** | 智能排产、异常预警、质量判定辅助、设备预测性维护 |

### 供（供应链与采购）

| 维度 | 内容 |
|------|------|
| **核心目标** | 保障物料、设备、资源按时到位，控制采购成本与风险 |
| **典型场景** | 采购寻源、供应商管理、来料检验、仓储管理、配送、库存控制 |
| **上游输入** | 需求计划、采购申请、供应商信息、库存数据 |
| **下游输出** | 物料、库存数据、交付状态、供应商绩效 |
| **关键角色** | 采购经理、供应商质量工程师、仓储主管、计划员 |
| **AI 提效机会** | 需求预测、供应商风险评估、库存优化、智能拣选 |

### 销（销售与市场）

| 维度 | 内容 |
|------|------|
| **核心目标** | 获取订单并稳定履约，平衡客户需求与内部产能 |
| **典型场景** | 市场开拓、报价、订单承接、交付承诺、客户协同、回款管理 |
| **上游输入** | 市场线索、客户需求、库存产能信息、价格策略 |
| **下游输出** | 订单、预测、交期承诺、客户满意度 |
| **关键角色** | 销售经理、客户经理、计划主管、财务 BP |
| **AI 提效机会** | 报价辅助、交期可达性预测、客户信用评估、订单风险预警 |

### 服（售后与服务）

| 维度 | 内容 |
|------|------|
| **核心目标** | 保障客户使用体验与问题闭环，驱动持续改进 |
| **典型场景** | 安装指导、售后支持、客诉处理、维修管理、备件支持、定期回访 |
| **上游输入** | 出货记录、设备档案、客户反馈、服务请求 |
| **下游输出** | 服务记录、问题闭环、改进建议、客户满意度 |
| **关键角色** | 客服主管、质量工程师、现场服务工程师、技术支持 |
| **AI 提效机会** | 客诉自动分诊、根因推荐、CAPA 生成、服务预测 |

## 跨链条协同关系

### 典型跨链条场景

| 场景 | 主链条 | 协同链条 | 协同关系说明 |
|------|--------|----------|--------------|
| 研发变更 | 研 | 供、产、服 | 研发变更会影响采购物料、生产工艺和售后备件 |
| 销售承诺交期 | 销 | 产、供 | 销售承诺交期会直接影响供应链备料和车间排产 |
| 售后客诉 | 服 | 产、研 | 售后客诉与现场故障会反向驱动生产改进和研发优化 |
| 采购交付异常 | 供 | 产、销 | 采购交付异常会传导到生产停线、销售延期、客户服务压力 |
| 质量异常 | 产 | 供、研 | 生产质量异常可能源于来料问题或设计缺陷 |

### 跨链条影响矩阵

```
                下游影响
         研    产    供    销    服
    研   -    ✓    ✓    ○    ✓
    产   ○    -    ○    ✓    ✓
上游  供   ○    ✓    -    ○    ○
    销   ○    ✓    ✓    -    ✓
    服   ✓    ✓    ○    ✓    -

✓：直接影响  ○：间接影响
```

## 定位方法与步骤

### 四步定位法

**步骤 1：识别核心业务目标**
- 当前场景最直接影响哪一个业务结果？
- 是质量、成本、交期、客户满意度还是其他？

**步骤 2：识别上游输入**
- 当前环节的输入来自哪里？
- 是谁提供了这些输入？
- 输入的形式是什么（物料、信息、指令）？

**步骤 3：识别下游输出**
- 当前环节的输出交给谁使用？
- 输出的形式是什么（产品、数据、决策）？
- 下游环节依赖什么信息或物料？

**步骤 4：确定主环节与协同环节**
- 如果场景横跨多个链条，确定主环节和协同环节
- 判断依据：核心目标、主要资源投入、主要 KPI 归属

## 输出格式规范

### 标准输出模板

```markdown
- **价值链环节**：[研/产/供/销/服]
- **协同链条**：[如有，列出协同环节]
- **上游依赖**：[列出关键上游输入，2-4 项]
- **下游影响**：[列出关键下游输出，2-4 项]
- **判断依据**：[1-2 句话说明定位理由]
```

### 示例输出

**示例 1：镀膜工艺监控场景**
```markdown
- **价值链环节**：产
- **协同链条**：研（工艺配方）、供（来料质量）
- **上游依赖**：工艺配方、来料镜片质量、设备状态
- **下游影响**：装配良率、光学性能、镀膜成本
- **判断依据**：场景核心目标是确保镀膜工艺稳定执行，属于生产制造环节
```

**示例 2：装配首件确认场景**
```markdown
- **价值链环节**：产
- **协同链条**：研（工艺验证）、供（来料齐套）
- **上游依赖**：首件样品、图纸与公差要求、BOM 与工艺文件
- **下游影响**：批量装配进度、首件良率、工艺参数优化
- **判断依据**：场景核心目标是换型后首件质量确认并放行，属于生产作业执行
```

**示例 3：客户投诉追溯场景**
```markdown
- **价值链环节**：服
- **协同链条**：产（生产追溯）、研（根因分析）、供（来料追溯）
- **上游依赖**：客户投诉信息、产品批次号、生产记录、检验记录
- **下游影响**：客户满意度、改进措施、质量成本
- **判断依据**：场景核心目标是快速响应客户投诉并闭环，属于售后服务环节
```

**示例 4：生产排程场景**
```markdown
- **价值链环节**：产
- **协同链条**：销（订单承诺）、供（物料齐套）
- **上游依赖**：销售订单、物料齐套状态、设备可用状态、工艺路线
- **下游影响**：产出节拍、交期达成率、在制周转、设备利用率
- **判断依据**：场景核心目标是优化生产作业计划，属于生产计划与执行
```

## 与 SKILL.md 的集成规则

### 在报告中的落点
1. **场景定位章节**：必须明确价值链环节及上下游依赖
2. **流程图节点**：必须体现研产供销服主链节点
3. **机会卡**：必须说明跨链条协同影响

## 注意事项

### 常见误区
1. **按部门归类**：错误地将生产部门的所有场景都归为"产"，应看业务影响
2. **忽略上下游**：只关注当前环节，不识别输入输出关系
3. **单点思维**：忽略跨链条协同影响
4. **静态思维**：忽略价值链的动态变化和反馈回路

### 特殊场景处理
- **横跨多链条**：输出主链条 + 协同链条，如"主：产，协同：供、销"
- **信息不足**：标注"D0 级"，基于有限信息给出最可能的定位
- **新兴场景**：如数据分析平台，根据服务对象定位（服务生产归"产"，服务销售归"销"）

## 价值链与 APQC 的映射关系

| 价值链 | 对应 APQC 一级分类 | 说明 |
|--------|-------------------|------|
| 研 | 2.0 Develop and Manage Products and Services | 产品研发与工艺开发 |
| 产 | 4.0 Deliver Physical Products | 生产制造与交付 |
| 供 | 4.0 Deliver Physical Products（部分） | 采购与供应链属于 4.0 和 12.0 |
| 销 | 3.0 Market and Sell Products and Services | 市场与销售 |
| 服 | 6.0 Manage Customer Service / 5.0 Deliver Services | 客户服务与服务履约 |

**注意**：价值链是业务视角的简化分类，APQC 是标准流程分类，两者互补使用。
